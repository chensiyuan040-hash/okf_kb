## B. 建库(每库一次性,以 kb-tech 为例)

```bash
# 一条命令(在 okf-kb 仓库根跑,或 PYTHONPATH 指向它):
python3 -m pipeline.init_vault /data/kb-tech --topic "技术知识库"
# 已有 .llm-wiki 会拒绝重复初始化(幂等保护)。一条命令做完:
#   .mcp.json(llm-wiki + okf-ops)· wiki_bootstrap · iwe init --okf +
#   注释 okf-index 绑定 · settings.json(synthesisLanguage: zh)·
#   buildGate 写门(默认开;--no-gate 关,不推荐)· git init + 首提交(identity 已配时)
# 可选:--model-id/--model-base-url/--model-key-env 配后台任务模型(默认用会话模型)。
# git 不代配:identity 未配(全局/系统/repo 级任一)则首提交跳过并警示,
```

## C. 日常入库(Claude Code 建库会话,标准动作)

**okf-ops MCP**(B 节 init_vault 已随 .mcp.json 写入)是建库会话的护栏:9 个工具
构成状态机 `begin → ingest/mapping → finalize(冻结)→ 人审 approve/reject →
commit → end`,锁格式与 pipeline 同源(import pipeline.locking),管线见
origin=session 自动跳批。vault 开了 buildGate(init_vault 默认开)后,bundle 写门
在无锁期与冻结期**物理拒绝**写工具——跳步是工具报错,不是脏数据。

开会话(锁、清单、盖章、commit 都由 agent 调工具完成):

```bash
cd /data/kb-tech && claude
```

开场白(直接抄;流程顺序不需要在提示词里交代,状态机在代码里):

> 调 okf-ops 的 kb_session_begin 取锁开工。把 raw-inbox 里的新原料按
> /opt/okf-kb/README.md 的"建库工作流速览"入库:kb_ingest_source 采集(已知
> 出处带上溯源参数),建页后 kb_record_mapping 登记。全部登记完调
> kb_finalize_batch 出归并清单,然后停下来等我审,不要自行 commit。

人审(对着 agent 转述的归并清单 + lint/交叉核对警示):

- 认可的页 → 让 agent 调 `kb_approve` 盖 verified(reviewer=你的 id);
  暂不确认的页 → deferred 带原因;
- 有问题 → `kb_reject` 带修正方向(解冻回 WORKING,agent 修正后重新 finalize 重审);
- 全部页 approved/deferred 后 → 让 agent `kb_commit`(本地 commit,归并清单随
  批次落 `outputs/merge-report-<batch>.md`)→ `kb_session_end` 放锁。

> git 只做本地留痕;vault 要不要配 remote、推到哪,由部署者自行决定,
> okf-ops 不碰 push。

BM 保密库:不进 raw-inbox,走 secret-vault SOP(解封 → 候选清单人审 →
`dispatch run --source bm --accept`),全程见 tools/secret-vault/README.md。

## D. 消费接入(平台侧,一次性,非 Claude Code)

平台后台 `mcp_server_configs` 注册 url 型 server ×4(8901-8904,transport=http,
command/args/env 不填)+ agent 绑定。验收清单见建库指南 §8 / AD-8:4 服务 active、
每 server `wiki_status` 返回本库、工具恰 4、宿主 `~/.llm-wiki` 内容不出现在结果。
