# 消费协议卡片(用库 agent 必读)

> 适用:内网消费会话(只读工具面:wiki_recall / wiki_search / wiki_read / wiki_status / wiki_lint)。
> 落点:用库 agent 的系统提示词 / 会话开头模板,整卡粘贴。
> 依据:真实库复核(2026-10-13,18 题逐项)——recall 零警示、preview 靠巧合、
> skeleton 页 Auto-preview 有误导空间;库"实际在用",消费侧防误导机制原本为 0。

## 五条硬纪律

```
1. 必须 recall 定位 → wiki_read 读全文 → 再回答;禁止只凭 preview 摘要作答。
2. 见到 flags / status: deprecated / superseded_by / stale_after 字段,必须向用户提示"该条已废弃/过期/被替代"。
3. 见到 vaultLabel(如 "📓 personal")的非本库条目,必须过滤或明确标注来源,不得当作本库内容。
4. 多来源内容矛盾且页面无任何标注时,禁止自行裁断;列出来源、声明"库内未标注裁决,请人工确认"。
5. status: skeleton 的页面(正文为 [LLM: …] 占位符)不当内容使用;即使其 Auto-preview 摘要看起来完整,也须报告"该页未整理"。flags 补丁部署后,skeleton 页在检索结果中以 `flags: [{kind: "skeleton"}]` 硬标记呈现——**见到该标记必须停用该条并向用户报告**。
```

## 第 2、5 条的判读依据:flags 四 kind

检索层补丁(建库指南 §8 补丁清单)在每条 recall/search 结果按页面 frontmatter
注入 `flags`,出现时按以下语义提示:

| kind | 含义 | detail | since |
|---|---|---|---|
| `superseded` | 已被替代 | 后继页 ID(读它拿现行内容) | stale_after(如有) |
| `deprecated` | 已废弃(无后继) | null | stale_after(如有) |
| `stale` | 已过期(stale_after 到期) | null | stale_after |
| `skeleton` | 未整理页(正文为占位符),内容待合成 | 固定文案(见左) | — |

> **部署状态**:`flags` 是本仓库对上游 bundle 的本地补丁。**本机**(仓库内 bundle)
> 已生效;**内网消费机待替换标准 bundle 后生效**——替换前,消费 agent 以 `wiki_read`
> 读到的 frontmatter(`status` / `superseded_by` / `stale_after`)承担提示义务;
> 替换后第 2、5 条以 `flags` 硬标记为准。

## 内网落地方式

- 与 `LLM_WIKI_READ_ONLY=1` 的 MCP 配置配套:纪律管 agent 行为,只读模式管工具面;
- **抽验方法**(克隆库,零污染):构造一页旧版页(`status: deprecated` + `superseded_by`)
  + 一条 personal 库条目场景 + 一个 skeleton 页,让消费 agent 按本卡回答——应主动带出
  替代提示、正确过滤跨库条目(不误当本库内容)、不误用 skeleton 页。
