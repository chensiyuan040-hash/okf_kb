# PRD:okf-kb 知识库演化与冲突治理(二期)

*工作标题——待确认。范围限定语:知识库建成之后的**运行演化期**——增量更新、新旧知识冲突、知识衰减与体系漂移的治理机制。*

## 0. 文档说明

本 PRD 面向需求方、知识库运维、知识人审与 okf-kb 侧交付,定义**演化期治理**要什么、为谁、怎么算做到。它回答三个问题:新知识进库如何不重复、不丢失;**新旧说法冲突如何处理、能否处理正确**;库的长期质量(衰减、漂移)靠什么维持。

**三条边界声明**(全文适用,不逐条重复):

1. **原料不可触碰**:全部治理动作只作用于知识页区与 state;**原料区(raw)永不改写**——与一期一致,无例外。
2. **单写者不破**:一切治理动作(合并、作废、复核、修正)同属写侧,受一期 FR-7 排他锁与"只提交本批路径清单"约束。
3. **消费面改动都要重打补丁**:本文凡涉及检索返回行为的需求,落地时均为只读补丁序列的扩展——升级重打 bundle 时补丁(含二期新增)会丢失,须随冒烟复检(建库指南 §8 的既有约束)。

## 1. 愿景

一期把四个源的知识**编译**成了可枚举、可追溯的图。但这张图是活的:每批新原料都在改写它。演化期有三个我们已经能看见的失效模式:

1. **重复增殖**。同一个概念在不同文档里有不同叫法,建图查重靠精确/词法匹配,翻不到就新建一页。每漏一次,同一件事就多一页;页越多,"哪些页讲的是同一件事"的判断越依赖人。这是复利型失效——不治理会越滚越快(R10 已识别风险,本文给出机制)。
2. **冲突静默**。老文档写了 A 方案;后来没人改它,而是新写了一篇 B 方案。系统不知道两页是取代关系,都把"有效知识"供出去;有人问,可能拿到已经作废的 A。更糟的是两页互相矛盾且谁都没改——系统完全不知道有分歧,两个答案各答一半。
3. **衰减无感**。页建成后再无人复核。"当前环境配置"这种今天对、三个月后不对的页,永远以"有效知识"的身份被检索。

**本文的赌注:演化期能不能变好,不取决于"能不能自动裁决冲突"——而取决于把冲突可见化、把保证级别分层明示。** 假装语义冲突可自动处理,比承认它处理不了更危险:用户会信任一个其实在悄悄选边或悄悄沉默的系统。所以本文的第一交付物不是"更强的自动化",而是**一个诚实的保证层级 + 让每一层可被验证的机制**:

| 层 | 管什么 | 保证级别 | 兜底手段 |
|---|---|---|---|
| **机械保证层** | 结构性问题:链环、悬空指针、状态非法、字段缺失、队列越期 | **可机械保证(门/校验/脚本),不依赖模型** | 质量门扩展项 + lint + 巡检 |
| **流程保证层** | 信号型问题:同 key 变更、对账发现的删改、显式冲突的裁决闭环 | **流程可保证:必被检出、必有归口、必有留痕**——但"检出"不等于"已解决" | 冲突清单 + 裁决流转 + 复核队列 |
| **语义尽力层** | 判断型问题:隐式替代、事实矛盾、重复页语义等同 | **不保证检出,不保证正确**——只在检出时禁止静默处理;**漏检必须被承认为已知边界** | 入库比对纪律 + 人审抽查 + 别名表沉淀 |

三层的关系:**上层失败不能伪装成下层已处理**。系统里任何"冲突不存在"的结论,必须能回答它出自哪一层——没有比对记录的"干净"批次,与"比对后无冲突"的批次,在任何报表中不得同形呈现。

## 2. 目标用户与关键旅程

### 2.1 待办任务(JTBD)

- **(运营 / 功能)** 我要知道库这一天/这一个月的质量趋势——重复页在变多还是变少、有多少页过期了、有多少冲突挂着没裁——这样我能安排治理投入。
- **(运营 / 情绪)** 我不怕库里"有"冲突,我怕的是**不知道有冲突**;给我一份全量、可查、可消项的清单,我按节奏消。
- **(审计 / 判断)** 我要能回答"某条知识什么时候被谁判定过时、依据是什么",而不只是"它现在没了"。
- **(消费侧用户 / 信任)** 我拿到的答案如果基于一条已被替代或存在分歧的知识,我必须**在答案里就看到这一点**,而不是自己撞上。
- **(建图代理 / 执行)** 我处理每份新原料时,要有明确的动作规范:先搜、比对、记录结论、把信号交给清单——而不是靠我"自觉"。

### 2.2 关键用户旅程

*人物沿用一期(运维陈工、知识人审王工)。情节由机制推演 `[ASSUMPTION: 旅程非用户访谈产出;若有真实案例以其为准替换]`。*

- **UJ-1. 王工裁决一次"疑似替代"(隐式替代的完整闭环)。**
  - **入口状态:** 批次报告显示本批入库比对产生 1 条"疑似替代"信号:新原料《XX服务部署规范 V2》与既有页《XX服务部署方案》主题重合。
  - **路径:** 他从批次报告打开冲突清单条目 → 对照两页内容与来源(新政出自变更单,更权威)→ 裁决"替代"。
  - **高潮:** 裁决后,旧页进入 `deprecated` 且建立替代链,检索返回旧页时带上"已被 V2 替代"的标注——**不做物理删除,历史可追**。
  - **边界情况:** 若两页其实是不同范围的内容(误报),他裁决"非替代",系统记住该信号,同对页面不再重复骚扰;**误报不算失败,漏检才是**。

- **UJ-2. 陈工做一次到期的月度复核。**
  - **入口状态:** 复核队列本周到期 12 页,按责任人分组,附各页摘要与上次确认时间。
  - **路径:** 他逐页三选一:仍有效(一键确认,时钟重置)/ 需重写(进修正范围)/ 作废(走 B 域替代流程)。
  - **高潮:** 12 页里 11 页在五分钟内确认完毕,只有 1 页需要真正重写——**复核成本被压缩到"点头"级别**,才可能长期坚持。
  - **边界情况:** 某页责任人已离职/无人署名 → 该页进"无主页"清单,升级给运维指派;**不得因无人认领而静默跳过**(跳过等于永久有效)。

- **UJ-3. 人审打回引发的一次系统性纠偏。**
  - **入口状态:** 连续三批的抽样人审都出现了同一问题类型:"entity 页把流程描述写成平铺列表,丢了条件分支"。
  - **路径:** 第 3 次出现触发偏差复核 → 检查建图纪律提示词 → 发现该类型页的指引缺失 → 补指引并记录调整结论。
  - **高潮:** 后续批次同类打回清零——**修的是纪律,不是逐页**。
  - **边界情况:** 若复查结论是"提示词没问题、是输入质量差"→ 结论同样留痕,并转入与源侧沟通;不留痕的"复查过"不算数。

## 3. 术语表(增量)

*一期术语表继续生效;以下为本文新增,用词以本表为准。*

- **演化期** — 知识库首次建成之后的运行阶段;本文的全部范围。
- **入库比对** — 每份新原料在建图前,与既有相关页做的一次显式一致性检查,产出**比对结论**(无信号 / 疑似替代 / 疑似矛盾)。比对是建图纪律的一部分(FR-A1),**比对记录的存在性可机械检验**。
- **冲突清单(conflict list)** — state 的一等产物,登记全部冲突条目及其生命周期 `{冲突 ID, 类型, 涉及页, 检测来源, 首次检测批次, 状态, 裁决人, 结论, 日期}`。与一期"删除/移动清单"(FR-5)同类同域。
- **冲突三型** — ①**显式替代**:同一源 key 内容变更(一期 FR-3/FR-4 信号);②**隐式替代**:不同源 key 的新内容取代既有页(机器只能提出"疑似");③**事实矛盾**:两处内容对同一事实给出不一致陈述。三型的共同要求:检出后禁止静默处理(见 FR-B4)。
- **替代链** — 由 `supersedes` / `superseded_by` 字段构成的页面替代关系链;须无环、双向一致、可整链读出(FR-B7)。
- **别名表(alias map)** — 页面 ⭢ 别称集合的登记表,由人工裁决或精确匹配确认后写入;建图查重与消费检索共用(FR-A2)。
- **复核(re-verification)** — 对已建成页面"是否仍然有效"的确认动作,结论三选一:仍有效(时钟重置)/ 需重写(进修正范围)/ 作废(走替代流程)。到期未复核的页称 **stale 页**。
- **复核三要素** — `owner`(责任人)、`review_cycle`(复核周期)、`last_verified`(上次确认时间);每页必有(FR-C1)。
- **重复候选** — 疑似同一概念的既有页面组;精确命中(别名/ID)直接生成**合并建议单**,语义相似只进候选池等待人工(FR-D2)。
- **合并建议单(merge proposal)** — 可一键批准/拒绝的合并提案文件;批准后执行链接重定向与 canonical 选取。
- **治理动作** — 演化期的一切写侧操作(裁决、合并、复核、修正、巡检修复);同受单写者锁约束。
- **保证三层** — 机械保证层 / 流程保证层 / 语义尽力层(§1);任何质量标准引用时必须指明所据层级。

## 4. 功能需求

### 4.0 实施前提:页面更新能力缺口

**静态验证事实(2026-10-12):** `wiki_ensure_page` **只创建、不更新**——目标页已存在时直接返回 no-op,不读不写不改;bundle 无 merge / deprecate / relink 工具(验证记录 二.2.2 / 二.2.7)。页面更新当前唯一可行路径是**编辑文件 + 元数据重建**(内容会被收录),代价是**丢失事件记录**(events.jsonl 不含正文与历史,无法找回旧版本)。

**动态实测(2026-10-12,试验库):** 该路径全链路走通——编辑 `wiki/**/*.md` → `wiki_rebuild_meta` → 页面/字段全部收录 → iwe 查询、体系树、元数据展示正常(验证记录 §3.3);代价坐实:全部手写编辑与 rebuild 在 events.jsonl **零记录**(仅 bootstrap + capture 共 5 条)。**且此路径即官方流程**:`wiki_ingest` 在模型不可用时的降级指引,本身就是让调用方 agent 手工编辑 `wiki/` 下的文件完成合成——受控编辑+重建是流程内的既定方式,非绕行。

**因此:** 域 B/C/D/E 的全部治理动作(置 `deprecated`、写替代链字段、改挂载关系、合并、复核确认)**都依赖一条尚不存在的可追溯更新路径**。该路径形态为实施前提(§11 Q-E9;候选 2"受控编辑+重建"已实测,评估底稿见 addendum §4bis),在选定并落地前:

1. 治理动作只允许以**人工受控操作**执行(先取锁 → 动作 → 记录),不得无人值守;每次操作进治理台账(FR-F3)。
2. 任一页面变更可归因(执行人、时间、依据):选定工具路径前由台账承担,选定后由工具事件承担。
3. **纪律表述修正**:验证推翻"绕过工具手写进不了图谱"(实测:手写内容仍被 registry 收录);准确的不变式是——**绕过受控流程的写入丢失事件记录与归因**。运维文档与建图纪律须按此表述(回写建议,不擅自改一期 final 文档)。

### 4.1 域 A:增量更新的正确性

**描述:** 新原料进入既有库时,不重复建页、不丢失引用、失败可续。实现 §1 失效模式 1 与 3 的机制底座。

#### FR-A1:入库比对纪律

每份新原料在建图前,与检索命中的既有相关页做**显式一致性比对**:给出比对结论(无信号 / 疑似替代 / 疑似矛盾)。比对结论无论有无信号,**均记入批次产物**。比对是建图代理的固定动作,不是建议。

`[实现注记]` 查重工具须用 `wiki_recall`(词法层对换叫法鲁棒,实测"网络问题处理/网络异常"均召回已有页);`wiki_search`(registry 名搜)漏检显著("网络异常"零结果),不得用于查重。recall **混合个人库命中**(带 `vaultLabel` 标注),判"已有页"时须过滤(验证记录 §3.2)。

**可测后果:**
- 每批次报告含"入库比对记录":逐原料列出命中页与比对结论。
- 比对记录的**缺失**可被机械检出(门扩展项)——比对记录与原料数不匹配的批次,按异常批次处理。
- 检出"疑似替代 / 疑似矛盾"的条目自动进入冲突清单(FR-B5),不由建图代理自行裁决。
- 建图代理**禁止**对既有页内容做静默删除或单向覆盖:任何删除既有陈述的动作,必须引用对应的裁决记录(FR-B4)。

**范围外:**
- 比对结论的语义准确率(属保证三层之"语义尽力层",用抽样人审监控)。

#### FR-A2:别名表

系统维护别名表:人裁决"两页为同一概念"或"某别称指向某页"后,别称写入别名表;建图查重与消费检索**同时使用别名表**。

`[已验证]` registry 的 `aliases` 字段已存在且**参与召回打分(权重位)与精确检索**——机制落点现成,无需补丁;别名**写入路径**随 §4.0 更新路径。**动态实测(召回强效)**:概念页登记别名后,换叫法查询得分 26.6 → **151.6** 并升至首位;纯别名新词查询直接命中 146.6(验证记录 §3.2)。写入成本极低(增数组项 + 重建)。

**可测后果:**
- 用任一已登记别称做精确检索,命中同一页面。
- 别名表写入仅有两个来源:人工裁决(含冲突裁决、合并批准)、**精确匹配**(规范化名/ID 完全相等);语义相似不得自动写入。
- 每条别名可追溯写入来源与日期。
- 别名表与 keymap 同域存放、同受备份保护。

**范围外:**
- 全自动同义词挖掘;跨库(跨 vault)别名共享。

#### FR-A3:前向引用占位与回填

新原料引用了尚未入库的概念(其页将在后续批次建成)时,引用不得静默丢弃:写为**可识别的占位形态**,待目标页建成后回填为正常链接。

**可测后果:**
- 占位形态可被检索识别:门 1(链接结构)将占位计为"待回填"而非断链,两类计数分开呈现。
- 目标页建成后,占位被回填,占位计数下降。
- 占位超期未回填(超过 N 批,部署期钉死)→ 进冲突清单告警。

**范围外:**
- 跨 vault 的前向引用。

#### FR-A4:失败批次的待修页进场

一期 FR-10 规定失败批次"已建页面保留待修";本文补齐**进场路径**:失败批次的待修页清单落 state,下批开工读取;修正方式二选一(重跑该批,幂等收敛 / 人工修正),**二者必择其一并留痕**。

**可测后果:**
- 失败批次在 state 生成"待修页清单";该清单可枚举。
- 待修页在后续批次中被纳入修正范围,或在清单中显式标注"忽略 + 理由";**不存在静默关闭**。
- 重跑同一批与首次成功执行结果一致(复用一期 FR-3 判据)。

**范围外:**
- 差异化的逐页重跑调度(一期 FR-5 精神:不重捕内容未变条目;重跑以获得收敛为准)。

#### FR-A5:双形态并存的操作纪律

演化期同时存在**人工建库会话**与**流水线批次**;治理动作(裁决、合并、复核、修正)与批次同属写侧。操作顺序固定:先停调度、再取锁、后动作。

**可测后果:**
- 治理动作与流水线批次互斥(排他锁),并发时恰一方成功、另一方可判失败(复用一期 FR-7 判据)。
- 锁元数据含**动作类型**(批次 / 人工建库 / 治理),排障可回答"谁持着锁、在做什么"。
- 遇锁跳过记录 `skipped_locked` 的既有语义不变。

**范围外:**
- 治理动作的在线热更新(动作期间库对消费面只读不变,见 8 NFR)。

### 4.2 域 B:冲突治理

**描述:** 冲突三型(显式替代 / 隐式替代 / 事实矛盾)的检出、登记、裁决、留痕与消费侧呈现。这是本文的核心域,实现 §1 失效模式 2 与赌注的"流程保证层"。

#### FR-B1:显式替代的级联处置

同一源 key 内容变更新建 SRC 时(一期 FR-4),旧页置 `deprecated` 并把级联做完:①替代链建立(FR-B7);②引用旧页的页面**保留引用但可见地降级**(由消费侧标注,不批量改写引用方正文);③旧页所在的枢纽页成员关系更新(移除或标注,由建图代理执行、门 3 复核)。

`[实现注记]` 级联动作(状态置位、链字段写入、挂载更新)依赖 §4.0 更新路径;bundle 无 deprecate 工具,"置 deprecated" = 写 `status` 字段 + 重建(验证记录 二.2.7)。

**可测后果:**
- 变更发生后:新页可读出替代的旧页;旧页状态为 `deprecated`;替代链完整。
- 引用旧页的页面数量可枚举(级联清单进批次报告)。
- 级联动作(supersedes 写入、状态置位、枢纽关系更新)在同一批次内完成,不留"半级联"——存在半级联状态的批次按异常批处理。

**范围外:**
- 批量改写引用方正文(引用方是否改由后续批次按常规原料处理)。

#### FR-B2:隐式替代的检出与裁决

不同源 key 的新内容**疑似取代**既有页时(入库比对或巡检信号),登记为"疑似替代"进冲突清单;由人裁决,结论四选一:**替代**(触发 FR-B1 级联流程)/ **并存**(两页都有效,可加交叉引用)/ **合并**(走 FR-D2)/ **误报**(记录并记忆)。

**可测后果:**
- 每条疑似替代在冲突清单有完整生命周期:检出 → 待裁决 → 已裁决(四结论之一)→ 关闭。
- 裁决"替代"后,消费侧行为立即变化(旧页返回带替代标注,见 FR-B5)。
- 裁决"误报"后,同一对页面的同一信号不再重复生成条目。
- **未裁决的疑似替代不得影响消费行为**(不预判、不隐藏)——检出到裁决之间,两页照常返回。

**范围外:**
- 自动裁决替代关系(即使高置信)。

#### FR-B3:事实矛盾的检出与呈现

入库比对或事后发现两处内容对同一事实陈述不一致时,登记"事实矛盾"进冲突清单;裁决结论:以甲为准 / 以乙为准 / 两者都对(适用场景不同,加条件说明)/ 存疑(保留分歧标注)。

**可测后果:**
- 冲突条目录入双方页 ID 与矛盾摘要(摘要仅供宿主侧与本库治理视图,不外发——内容边界见 §9)。
- **裁决前,矛盾双方页面均保持可检索,且返回带分歧标注**(FR-B5)——系统不替用户选边。
- 建图代理静默抹平矛盾(删除一方陈述而不留裁决记录)可由存在性检查机械检出:删除既有陈述而无对应裁决记录 = 违规。

**范围外:**
- 自动判定孰对孰错;矛盾的时效自动加权(时间新者胜——**明确拒绝**,时效不等于正确)。

#### FR-B4:静默处理禁令(跨型通用)

三型冲突检出后,**禁止任何角色的静默处理**:不得静默删除、不得静默选边、不得静默忽略。一切"处理"必须落为清单条目的状态流转,含操作者、依据与日期。

**可测后果:**
- 冲突清单条目的每次状态变更可追溯(谁、何时、依据)。
- 冲突条目关闭必须有裁决记录;无记录的关闭可机械检出。
- 质量门扩展项的机械判据:本批对既有页内容的删除动作,与冲突清单裁决记录的**对账**——有删除无裁决 = 阻断。

**范围外:**
- 对"未检出"冲突的约束(属保证三层之语义尽力层,承认不保证)。

#### FR-B5:冲突清单与消费侧三档处置

冲突清单为 state 一等产物(FR-B5=清单机制本身);消费侧按条目状态**三档处置**:

| 页面情形 | 消费侧行为 |
|---|---|
| `deprecated`(已被替代) | **照常返回 + 标注**("此页已被《X》替代,替代日期 Y" )——不隐藏:隐藏会造成知识真空,且用户有权知道"这里曾有一条被替代的知识" |
| 存在未裁决矛盾 | 双方**均可返回 + 分歧标注**("此页与《Y》对 Z 的陈述存在分歧,尚未裁决") |
| stale(过期未复核,域 C) | **降权 + 过期标注**("此页超过复核周期未确认") |

**可测后果:**
- 上述三类标注**在检索返回载荷中结构化存在**(字段形态,非仅正文文字)——弱模型消费时不需要"自觉"就能转述给用户。
- 召回排序:`deprecated` 页在同主题竞争下不排首位;stale 页降权(降权幅度部署期钉死)。
- 告警形态沿用一期内容边界:外发消息只含冲突 ID、类型、计数——**不含标题、路径、正文**。
- 清单存量与账龄可读:超期未裁决条目告警(阈值部署期钉死)。

**范围外:**
- 消费侧提供"隐藏全部 deprecated 页"的开关(未来若需要,走版本化配置变更)。

`[NOTE FOR PM]` 本 FR 落地需扩展只读补丁(返回载荷增标注字段)。`[已验证]` 补丁**已实测**(试验库副本,未动仓库):`searchWiki` 返回组装(`mcp-server.mjs:236843` 起 map)**单锚点替换约 15 行**,deprecated/stale 页返回 `flags: [{kind: "superseded"|"stale", detail, since}]`,其余页契约不变(既有字段原样、新字段可选出现);副本冒烟通过(16 工具)。**维护成本才是主要代价**——单文件 bundle 无扩展点,每次重打上游都要重打全部补丁。冒烟脚本须增加"标注字段存在性"断言,并补 `wiki_read`(现 REQUIRED_TOOLS 未含,验证记录 §3.5)。

#### FR-B6:清单的账龄与升级

冲突清单条目按账龄分层(新 / 待裁决 / 超期);超期条目按既定节奏升级提醒(周报汇总,随批次报告归档)。

**可测后果:**
- 任意时刻可回答:清单存量、各账龄段数量、最老条目年龄。
- 超期条目出现在周报;周报无"静默跳过"。

**范围外:**
- 自动关闭长期未裁决条目(账龄长不等于不重要)。

#### FR-B7:替代链字段与校验

页面 frontmatter 增加 `supersedes` / `superseded_by` 链接字段(OKF 规范当前无此字段,属本系统扩展 `[已验证]` 兼容性已核实:自定义字段不被拒绝,registry 条目**平铺保留**、iwe 元数据完整读出展示——实测写入 `superseded_by` 后 `iwe find` 直接可见,验证记录 §3.3);lint 校验:目标存在、双向一致、**无环**——`[实现注记]` iwe 的 schema 校验**无引用类型校验、无跨页一致性能力**,该项校验须自建脚本(验证记录 一.1.4)。

**可测后果:**
- 链环、悬空指针、单向不一致均为阻断级 lint 项。
- 任意页可整链读出替代历史("此页替代了 A,A 替代了 B")。
- 字段形态受版本管理;升级兼容项入一期 FR-22 清单。

**范围外:**
- OKF 上游采纳该字段(可反馈,不以本文为承诺)。

### 4.3 域 C:知识衰减与复核

**描述:** 让"仍然有效"成为一个需要持续表态的状态,而不是默认值。实现 §1 失效模式 3。

#### FR-C1:复核三要素

每页具备 `owner` / `review_cycle` / `last_verified`;新页建成时赋予,存量页批量补赋(迁移路径见下)。

`[已验证]` **字段映射成立**:`last_verified` 映射 OKF `verified {by, at}`(actor 约定 `human:` / `process:` 天然区分人审与机器确认);到期时刻映射 `stale_after`。`owner` / `review_cycle` 为**自定义字段**——规范明确允许、registry 透传保留,但其**消费逻辑(谁读、谁校验、谁到期触发)须自建**(验证记录 一.1.2 / 二.2.3)。`[实现注记]` **stale_after 格式须用日期(YYYY-MM-DD)**:iwe schema 将其硬校验为 `date`,写 ISO8601 时刻(`…T00:00:00Z`)会 validate 失败——实现比 OKF SPEC 更窄,写入规范须钉死格式(验证记录 §3.4)。

**可测后果:**
- 每页可读出三要素;缺失三要素的页面可枚举(门 2 模式校验的扩展项,缺失=阻断)。
- 存量迁移:既有库页面的三要素补赋有一次性批处理路径与完成判据(补赋完成率可算)。
- `review_cycle` 取值集固定(如 90/180/365 天,部署期钉死),不允许自由文本。

**范围外:**
- 按内容类型自动推荐周期(初始由建图代理+人审标注,自动推荐属远期)。

#### FR-C2:到期复核流程

`last_verified + review_cycle` 到期 → 页进入**复核队列**;复核动作三选一(仍有效 / 需重写 / 作废);批量确认支持;动作记事件。

**可测后果:**
- 复核队列可枚举(按责任人分组、按到期时间排序)。
- "仍有效"一键确认:动作后 `last_verified` 更新、出队,全流程可审计。
- **队列为空的周期,报告显式标注"本周期无到期项"**,不记为"已复核"(沿用一期 FR-12 空样本原则)。
- 无人认领页(责任人缺失)→ 进"无主页"清单升级指派,不静默跳过。

**范围外:**
- 复核动作的自动通过(如"到期后仍被召回则自动续期"——**明确拒绝**:被检索≠被验证)。

#### FR-C3:过期的检索处置

stale 页在消费侧**降权 + 标注**(与 FR-B5 同机制);复核完成后自动恢复。

`[实现注记]` **动态实测:当前对 stale_after 写入"零消费"**——写入过期日期后检索得分与排序完全不变;业务代码对该字段仅存储透传(2 处字段白名单)、对 `deprecated` 零消费(验证记录 §3.4)。被替代旧页因正文匹配度高反而排在替代者之前——本 FR 与 FR-B5 的全部消费行为均属新增改造。`[已验证]` 补丁路径同 FR-B5(实测已通)。

**可测后果:**
- stale 页在同主题召回的排序低于非 stale 页(幅度部署期钉死)。
- 复核通过后,下一批的索引刷新后标注消失。
- 标注与降权不破坏"答案带来源":来源仍指向页本身。

**范围外:**
- 对 stale 页的自动隐藏。

#### FR-C4:时效性标注(可选机制)

对时效性明显的内容(版本号、当前配置、有效期),支持显式失效日期标注;到期即进复核队列(不等 `review_cycle`)。

**可测后果:**
- 标了失效日期的页,到期当日必进队列(可由日期复算)。
- 是否标注由建图纪律与人审标注决定——**不要求自动判定**哪些内容时效敏感。

**范围外:**
- 自动识别时效敏感内容。

### 4.4 域 D:体系漂移与熵增

**描述:** 跨批次累积的结构退化(体系漂移、重复页、历史断链)的周期性治理。一期门体系只管**本批**,本域管**存量**。

#### FR-D1:周期性全库巡检

按周期执行全库巡检(不只本批):孤儿、断链、未挂载页、空壳枢纽、成员列表与成员页回链不一致、待回填占位超期。产出**巡检清单**,发现项进冲突清单或修复队列。

**可测后果:**
- 巡检周期固定(部署期钉死),超期未跑告警。
- 巡检发现项可枚举、可消项、可算趋势。
- 与门体系分工明确:**门管本批提交前,巡检管存量周期**——两者发现同一问题的处理归口不同,不重复告警。

**范围外:**
- 巡检的自动修复(修复动作一律走治理动作留痕)。

#### FR-D2:重复候选与合并

重复治理**双档**:

| 档 | 条件 | 动作 |
|---|---|---|
| 精确档 | 别名/ID 完全命中 | 生成合并建议单,**可配置为自动执行** `[ASSUMPTION: 首版建议一律走建议单人工批准;自动执行留作配置开关]` |
| 语义档 | 内容相似(建图代理标记或巡检信号;可用信号源:iwe stats 的 **similar-page** 报告 `[已验证存在,advisory 性质]`) | 进候选池,**只出建议单,人工批准** |

合并执行(批准后)机械完成:出入链接重定向至 canonical 页、去自环与重边、canonical 选取规则(成员多的页优先,部署期钉死)、被并方 provenance **全量保留**在 canonical 页。

`[实现注记]` **merge / relink 工具不存在**(验证记录 二.2.1)——合并执行无现成工具,须自建脚本或人工受控执行。首版建议:**建议单 + 人工受控执行流程**落地;自建自动化工具为增强项(依赖 §4.0 更新路径)。

**可测后果:**
- 合并建议单形态固定(涉及页、建议 canonical、依据),可一键批准/拒绝。
- 合并后:原页链接重定向,**无新增断链**(门 1 复检);被并方 provenance 在 canonical 页可追。
- 合并动作进替代链(`superseded_by`)——合并即一种替代,历史可读。
- 拒绝的候选**记忆**,同一对页面不重复出单(除非内容显著变化)。

**范围外:**
- 自动合并语义相似页(**明确拒绝**);页面物理删除(**一期非目标延续**)。

#### FR-D3:历史遗留修复归属

跨批次断链、孤儿、错挂载的修复:由巡检发现(FR-D1)→ 进修复队列 → 由建图代理在后续批次中执行(作为治理动作)或人工会话处理;每条修复留痕。

**可测后果:**
- 每个存量问题有归属(巡检发现→队列→修复/显式忽略+理由)。
- 修复动作不绕过写侧工具(门 4 检出机制延续)。

**范围外:**
- 批量自动改写历史页正文的修复(修复以挂载关系与链接为主,正文改写走常规建图)。

### 4.5 域 E:人工修正回路

**描述:** 人审打回、人工修正、系统性偏差纠偏的完整回路——机器产物与人工修订的共存规则,以及"同类错误反复出现"的升级路径。

#### FR-E1:人工修订的保护与共存

`[已验证]` **风险形态与初稿假设不同**:现行工具**根本不触碰已存在页**(ensure_page 只创建,验证记录 二.2.2)——人工修订天然不被工具覆盖;真正的风险来自**更新路径缺失下的受控手写操作**(误覆盖且无留痕)。因此本条重心:①含人工修订标记的页面,任何受控改写必须留裁决/指令依据;②人工来源与机器来源用 actor 约定(`human:` / `process:`)区分——现成能力(与 FR-C1 同源)。

**可测后果:**
- 人工修订标记在页上可读(`verified.by` 的 `human:` 形态或等价约定)。
- 对含人工修订页面的受控改写,若无裁决/指令记录 = 违规(与 FR-B4 同款对账检出)。
- 人工修订同样走受控流程——绕过即丢事件与归因(§4.0 修正后的纪律,取代"门 4 检出"的旧表述)。
- 覆盖与保留的判定有留痕,可审计。

**范围外:**
- 人工修订与机器内容的自动融合(首版以"保留 + 提出待裁决"为准)。

#### FR-E2:系统性偏差反馈

同类问题(同一问题类型)在**连续批次**或**多页**重复出现(阈值部署期钉死,建议:同类型连续 3 批或单批 ≥5 页)→ 触发建图纪律/提示词**复查动作**;复查结论(调整 / 不调整 + 理由)记录归档。

**可测后果:**
- 偏差信号可从人审记录(一期 FR-12 回填字段)按类型聚合复算。
- 触发后存在复查动作记录;同一信号在复查完成前不重复触发(不骚扰)。
- 复查结论为"不调整"时,同样留痕并注明后续处置(如转源侧沟通)。

**范围外:**
- 自动改写提示词资产(调整永远是人做的动作)。

#### FR-E3:打回页的闭环

一期 FR-12 的打回页:"在下一批被修正或显式说明不予修正"——本文补齐状态流转:打回 → 修正范围 → 修正完成(复检)/ 不予修正(+理由)→ 关闭。全流程状态可见。

**可测后果:**
- 任意打回页可回答当前状态与归属批次。
- 关闭需复检或理由,无静默关闭(与 FR-B4 同精神)。

**范围外:**
- 复检的自动化语义判断(复用抽样人审的人工动作)。

### 4.6 域 F:治理观测

**描述:** 让库的演化健康可读数——不只看单批,看趋势;不只看页数,看质量。

#### FR-F1:库健康三指标与冒烟扩展

`wiki_status`(一期 FR-16 的"状态"工具)扩展输出三个指标:**孤儿率、stale 占比、疑似重复候选数**;连同既有总量、健康判定。召回冒烟与工具集冒烟**增加断言**:只读模式下标注字段存在(FR-B5)。

**可测后果:**
- 状态工具返回含三指标,且可从库数据复算(指标可信)。
- 只读模式冒烟新增断言:返回载荷含替代/分歧/过期标注能力——断言失败视为补丁丢失,不得静默通过(复用一期 FR-13 机制)。
- 三指标进批次报告与周报。

**范围外:**
- 指标的行业对标基准(自比趋势即可,首版不设绝对阈值)。

#### FR-F2:演化趋势留档

三指标连同页数按周期快照留档(state 内),形成时间序列;趋势可读(近 N 周升/降)。

**可测后果:**
- 可回答"从 X 到 Y,孤儿率与重复候选是升是降"。
- 快照随备份恢复域一并保护(一期 FR-21 的域扩展)。

**范围外:**
- 可视化面板(首版以文件+报告形态)。

#### FR-F3:治理动作台账

治理动作(裁决、合并、复核、修正、巡检修复)的台账视图:谁、何时、对什么、依据什么、结果如何。

**可测后果:**
- 台账可按时间/角色/类型检索。
- 每个冲突清单条目的全生命周期可从台账重建。
- 台账与事件溯源(写侧工具)一致,不另造数据源。

**范围外:**
- 跨库治理台账合并(一期非目标延续:不做跨库统一视图)。

## 5. 非目标(显式)

- **不做自动语义裁决。** 隐式替代与事实矛盾的"谁对"永远由人定;时间新者胜、来源权威加权等启发式**不被采纳为自动裁决依据**(可作裁决辅助信息呈现)。
- **不做物理删除。** 一期非目标延续:作废=置状态+替代链,页与历史永在。
- **不做消费侧全隐藏模式。** deprecated/stale 页默认照常可见+标注,不给"一键隐藏"开关(见 FR-B5 范围外)。
- **不做跨库冲突治理。** 四库各自的冲突在各自 vault 内处置(一期"不做跨库统一图谱"的延续)。
- **不做双时态查询。** 不提供"as_of 某时点库状态"的检索接口;历史由替代链+事件溯源承担。
- **不做自动术语/本体学习。** 别名表只沉淀确认过的关系,不自动挖掘。
- **不做质量性重建的自动化。** "库烂到重建"的触发线与成本评估列入开放问题,二期不自动执行。

## 6. MVP 范围

*阶段命名用 E(Evolution)避免与一期 P 阶段混淆;与一期排期的并轨关系待定(见 §11)。*

### E0:冲突可见化地基(必做)

- 入库比对纪律(FR-A1)+ 冲突清单(FR-B5/B6)+ 静默禁令的机械对账(FR-B4)。
- 显式替代级联 + 替代链字段与校验(FR-B1/B7)。
- 消费侧三档标注 + 冒烟扩展(FR-B5/F1 冒烟部分)。
- 复核三要素 + 到期复核流程(FR-C1/C2)。

**出口标准:** 增量批次可比对、可登记、可裁决、可留痕;消费侧能标注替代/分歧/过期;复核队列可跑一轮;全部冒烟通过。

`[注]` E0 全部依赖 §4.0 更新路径先落地——**E0 排期必须包含该实施前提**。

### E1:检测与合并增强

- 隐式替代检出与裁决流(FR-B2)、事实矛盾呈现(FR-B3)。
- 别名表(FR-A2);重复候选与合并建议单(FR-D2)。
- 前向引用占位(FR-A3)。
- 待修页进场与闭环(FR-A4/E3)。

**出口标准:** 三型冲突全部有检出信号与裁决通道;别名表可反哺查重。

### E2:回路与观测

- 系统性偏差反馈(FR-E2);周期性全库巡检(FR-D1/D3)。
- 健康三指标与趋势(FR-F1/F2/F3)。
- 时效性标注(FR-C4,可选)。

**出口标准:** 指标可读、趋势可看、偏差有升级路径、存量问题有巡检归属。

## 7. 成功指标

### 主要

- **SM-E1:重复增殖收敛。** 每批新增综合页中,后被判定为重复(合并/别名归一)的比例逐季下降;[ASSUMPTION: 起步基线待存量盘点后测定]。验证 FR-A2/D2。
- **SM-E2:冲突闭环率。** 冲突清单条目在 N 批内完成裁决(含"存疑"结论)的比例 ≥ 90%;N 部署期钉死(建议 4 批)。验证 FR-B2/B5/B6。
- **SM-E3:静默为零且可证。** 对既有页内容的删除动作与裁决记录对账,**无记录删除 = 0**;批次比对记录覆盖率 100%。验证 FR-B4/A1。
- **SM-E4:复核运转。** 复核队列到期项的周期消化率 ≥ 90%(确认/重写/作废合计);无主页数量有界且有指派。验证 FR-C2。
- **SM-E5:消费侧标注生效。** 抽样检索中,deprecated/分歧/stale 页的标注**随返回载荷出现**的比例 = 100%(机械断言,非抽样)。验证 FR-B5/C3/F1。

### 反向指标(明确**不**优化)

- **SM-C1:冲突清单长度趋零。** 清单清空可能是检测失效而非库变干净——以"检出-裁决"质量为目标,不以条目少为目标。制衡 SM-E2。
- **SM-C2:复核操作时长。** 不得为压缩复核时间改用更粗的周期或批量无差别确认;一键确认的前提是责任人真的看过摘要(该约束靠流程纪律承担,不设机械门)。制衡 SM-E4。
- **SM-C3:自动处置比例。** 自动化率不是目标;并入精确档自动合并是**能力**不是**成绩**。制衡 §1 赌注。
- **SM-C4:治理动作总量。** 动作多不等于治理好(可能是检测噪声);治理动作数只用于容量规划,不用于绩效。制衡 SM-E2。

## 8. 跨功能非功能需求(增量)

- **NFR-E1 治理不阻塞消费:** 治理动作与批次一致地受单写者约束,但消费面只读不受影响(一期 NFR-1 延续);治理期间的库状态对消费侧始终是"上一批完成时"的一致视图。
- **NFR-E2 标注字段的兼容性:** 消费侧新增标注字段不改变既有四工具契约的必填/返回形状的兼容部分(新增字段≠破坏);字段变更入版本记录(一期 FR-13 机制)。
- **NFR-E3 治理成本上限:** 常规复核队列的周人工耗时目标 ≤ [ASSUMPTION: 30 分钟/周/库,待实测校准];超限触发的是治理节奏评审,而非跳过复核。
- **NFR-E4 幂等:** 治理动作可重放:合并重放收敛、裁决重复提交幂等(同结论不重复生成转折)、复核重复确认幂等。
- **NFR-E5 离线一致:** 全部治理机制不引入新的联网依赖(一期 NFR-7 延续);复核与比对若使用模型,经既有建图模型通道(专用低权凭据、限流延续)。

## 9. 安全与合规(增量)

- **冲突清单与复核队列的内容边界:** 清单/队列的**本库治理视图**可含页 ID 与摘要(宿主侧,权限同库目录);**一切外发形态**(告警、周报外发)只含冲突 ID、类型、计数——不含标题、路径、摘要、正文(一期 §9.3 延续)。
- **BM 库的演化治理:** 全部治理动作(B 域全部、C 域复核)在 BM 库照常适用,但:①治理产物的外发形态同上收窄;②BM 页的作废/合并动作走既有"人工确认后处置"通道,不新增自动化(沿用一期 FR-6 白名单+人审精神)。
- **替代链与事件溯源即审计:** 替代链(FR-B7)与治理台账(FR-F3)共同承担"某条知识何时被判定过时、依据什么"的审计回答——审计不依赖会话记录(会话记录属平台侧,边界同 §9.1 一期)。
- **取回即扩散的既有边界不变:** 本文不改变一期 §9.1 的 BM 决策点与消费侧可见性取舍;消费侧标注机制(FR-B5)同样作用于 BM 库的 source 页。
