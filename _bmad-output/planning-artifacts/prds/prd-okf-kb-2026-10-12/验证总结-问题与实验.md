## 1. 你问的两个问题与答案

### Q1 增量更新知识库:怎么处理?能否处理正确?

**问题展开**:新原料进来,会不会重复建页?会不会把旧内容覆盖丢?错了能不能兜住?

**静态结论**

- 捕获工具 `capture_source` **无去重**:同一份材料重复捕获会产生多份 SRC(验证记录 二.2.9)——"跳过已处理"必须在上层自建。
- 建页工具 `ensure_page` **只创建、不更新**:目标页已存在直接返回"未创建",不看内容不比对(二.2.2)——重复建页会被它挡住,但**增量内容不会被并入**,静默丢弃。
- 好消息:目录索引(registry)是全量重扫生成的——**手写进库的内容都会被收录**,"手写进不了图谱"的说法不成立(二.2.3);真正的风险是绕过受控流程后**丢失事件记录与归因**。

**动态实验结论(实验 1,详见 §3.3)**

- 换叫法的重复页**可以搜出来**:后一份材料叫《网络问题处理方法》,用检索工具查"网络问题处理""网络异常",都能命中已有的《网络故障排查》页——防重复的第一道闸(先搜后建)真实可用。
- **但工具选错就会漏**:另一个搜索工具(registry 名搜)查"网络异常"零结果——查重纪律必须规定用对工具。
- **别名登记是最便宜的保险**:把"网络问题处理"登记为已有页的别名后,该查询命中分 26.6 → **151.6**,直接排第一。
- 诚实声明:试验库只有 7 页,"低漏检率"有乐观偏差,真实大库需重测。
- 另一个坑:检索会**混入个人库**(~/.llm-wiki)的结果,判"是否已有页"时要按标签过滤。

**能否处理正确的答案(分层)**:防重复(机械层)✅ 有手段且已验证;增量内容正确并入(语义层)⚠️ 系统不提供,靠"入库比对纪律 + 人工/模型判断";重跑幂等 ⚠️ 需编排层自建。**结论:机械部分可保证,语义部分只能"尽力而为 + 可见的台账"**。

### Q2 新旧知识冲突:怎么处理?能否处理正确?

**问题展开**:旧知识被新知识替代时,系统知不知道该废弃旧的?用户还能不能搜到旧的?矛盾的说法谁说了算?

**三种冲突形态**(问题域划分的产物):

| 形态 | 例子 | 系统现在能做的 |
|---|---|---|
| 显式替代(同源更新) | 同一份 SOP 出了 V2 | 无工具,只能手写字段(实验 2 验证可行) |
| 隐式替代(换叫法) | 《网络故障排查》vs《网络问题处理方法》 | 无任何自动能力;别名表可兜(实验 1) |
| 事实矛盾 | 两处说法不一致 | **完全没有检测能力**:lint 的"矛盾检查"只认正文里的一个字面标记,不做内容比对(二.2.6) |

**静态结论**

- bundle **无 merge / deprecate / alias / relink 任何治理工具**(二.2.1)——冲突关系字段只存在于设计稿,未实现。
- 作废一个页面的唯一路径 = 写 `status` 字段 + 重建(二.2.7)。
- 自定义替代字段写入后:iwe 完整识别展示 ✅;但**双向一致、无环校验** iwe schema 做不到,须自建脚本(一.1.4)。

**动态实验结论(实验 2/3/4,详见 §3.3)**

- **能标记**:给旧方案页写 `status: deprecated` + `superseded_by: SRC-...(V2)` + 替代注记,全部被系统收录,iwe 树/元数据正确展示;`supersedes`/`superseded_by` 字段全链路走通。
- **标记了也没人理(现状的残酷)**:标完"已废弃"后检索分数 92 → **102**——旧方案不仅不降权,**反而排在新方案前面**(因为正文匹配度高)。扒源码确认:两个字段在业务代码里**零消费**,纯存储。
- **补救可行(实验 4)**:在只读层打约 15 行补丁,旧页返回时带上 `flags: [{kind:"superseded", detail:"SRC-...(V2)", since:"2026-09-30"}, {kind:"stale", ...}]` 标注——实测成功、契约不破坏、冒烟通过。"照常返回 + 明确标注"的设计得到了可行性验证。

**能否处理正确的答案(三层保证)**:①机械层(可保证):标记字段、台账在对账——"每个冲突都有裁决记录"可用门禁卡死;②流程层(可保证):每个冲突必须走"检出 → 人工裁决 → 记录"的固定动作;③语义层(尽力而为,诚实声明):**"哪边是对的"系统不能裁决,也不应该自动裁决**——只负责暴露分歧、标注来源,把判断权留给人。这是 PRD 里"保证三层"的来由。

## 3. 实验记录(具体验证情况)

### 3.2 静态验证(18 条,摘要)

**iwe + OKF(8 条)**:①自定义 frontmatter 字段明确允许 ✅ ②trust 字段(verified/stale_after)定义确认 ✅ ③stale 无强制消费行为(仅建议 warn/refuse)④schema 校验无引用/跨页一致性能力 ⑤断链/孤儿检查在 iwe_stats(advisory)⑥图查询可表达"非 deprecated/孤儿"⑦inclusion 链接规则(独占一行)⑧iwe 无 `--root`,以 cwd 为库。

**pi-llm-wiki(10 条)**:①16 工具、**无任何治理工具** ②ensure_page 只创建不更新 ③registry 全量重扫、aliases 参与召回 ④events.jsonl 无正文历史 ⑤recall/search 返回形状与补丁点 ⑥lint 8 项、矛盾检测仅字面标记 ⑦无删除/废弃工具 ⑧WIKI_ROOT 隔离手段 ⑨capture 无去重 ⑩模型不可用时 ingest 静默降级。

### 3.3 动态验证(试验库四实验)

#### 实验 1:先搜后建漏检面

- **操作**:第二批原料《网络问题处理方法》(与已有《网络故障排查》同类换叫法)入库前,模拟建图代理做查重——对 5 组查询分别跑 recall 与 search。
- **结果**:

| 查询 | recall(词法) | search(registry) |
|---|---|---|
| 网络问题处理 | ✅ 命中已有页 26.6 | ❌ 仅返回新原料自身 |
| 网络问题 | ✅ 26.6 | ❌ 仅自身 |
| 网络异常 | ✅ 26.6 | ❌ **零结果** |
| 网络故障排查(正名) | ✅ 173.4 | ✅ 命中 |
| 丢包 | ✅ 9.6 | ❌ 零结果 |

- **附加发现**:recall 混合个人库命中(`vaultLabel: "📓 personal"` 标注);登记 aliases 后"网络问题处理"26.6→**151.6** 置顶、纯别名"网络异常处理"146.6。
- **结论**:查重必须用 recall;防重复的机械手段(检索 + 别名)真实可用。

#### 实验 2:手写编辑 + rebuild 更新路径(地基级)

- **操作**:对既有页执行全部演化动作——概念页内容合并、aliases 增补、`status: stable→deprecated`、`superseded_by`/`supersedes` 写入、正文替代注记;然后 `wiki_rebuild_meta`。
- **结果**:7 页全收录;iwe 查询/体系树/元数据展示全部正确;schema validate 通过(修正格式后);**events.jsonl 仅 5 条**(bootstrap×1 + capture×4),所有手写编辑与 rebuild **零事件**。
- **关键发现**:ingest 在无模型时的降级指引(6 步)本身就是"让 agent 手工编辑 wiki/ 文件"——**受控编辑+重建是官方流程内方式,非绕行**。
- **结论**:更新路径全链路可行;代价=无审计踪迹,治理台账是硬需求。

#### 实验 3:stale_after / deprecated 的消费行为

- **操作**:旧方案页写入 `status: deprecated` + `stale_after: 2026-09-30`(已过期),重建后观察检索。
- **结果**:分数 **92 → 102**,排序不降反微升,**排在新方案(V2, 24 分)前面**;源码对照:stale_after 仅 2 处字段白名单、deprecated 业务侧 0 处消费。
- **iwe 侧发现**:写 ISO8601 时刻(`…T00:00:00Z`)会被 validate 拒绝(要求 `date` 格式);validate 失败退出码=1(门机制可用)、通过时静默退出码 0。
- **结论**:现状"标记=纯文字",消费逻辑完全缺失——FR-B5/C3 是纯新增改造,需求确凿。

#### 实验 4:消费侧 flags 补丁实测

- **操作**:试验库内 bundle 副本,在 `searchWiki` 返回组装处(`mcp-server.mjs:236843` 起)**单锚点替换约 15 行**,给 deprecated/stale 页附加 `flags` 字段。
- **结果**:旧页返回带 `"flags": [{"kind":"superseded","detail":"SRC-2026-10-12-004","since":"2026-09-30"}, {"kind":"stale",...}]`;其余页契约不变;副本冒烟通过(16 工具);status 等工具正常。
- **结论**:FR-B5"照常返回+结构化标注"补丁成本极低、可行性坐实;唯一代价=上游重打需重放补丁。
