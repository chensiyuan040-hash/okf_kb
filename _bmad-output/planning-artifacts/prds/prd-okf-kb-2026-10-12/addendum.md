## 1. 业界调研提炼(2026-10-12,背景子代理产出)

标注:`[机]`=机械可自动/质量门可保证;`[义]`=需语义判断(LLM 或人工)。

**冲突治理模型**
- 冲突建模为类型边 SUPERSEDES / REPLACES / CONTRADICTS,配来源优先级可机械裁决;但"检测到分歧 ≠ 判定谁对"——企业内权威常隐性,"false consensus"是核心失败指标,应暴露分歧而非强行给单一答案。[机:关系边] [义:真伪裁决]
- TMS/AGM 可借三条:修订链 append-only(新值 supersedes 旧值而非删除);撤回沿 DERIVED_FROM/DEPENDS_ON 算影响闭包、级联标记"结论已失真",但级联**不**沿 SUPERSEDES 传播(防误伤);recovery 主动放弃。[机:闭包传播] [义:该撤哪条]
- 检测工程:embedding 分类器粗筛 + LLM 精判(降本约 60%);冲突分类 factual/temporal/opinion,时间型最常见。**对本项目的可用性:**粗筛依赖向量能力,内网词法检索下不可直接照搬;可替换为"词法交集 + LLM 精判"通道,精度待实测。
- 检索层组装模式(retraction ∈ hide|flag|surface_both;supersession ∈ hide|prefer_new|surface_both)四遍:事实去重 → supersede 重排 → 多样性回填 → 冲突标注。**本 PRD 采纳:** retraction=flag、supersession=surface_both(FR-B5)。

**知识衰减**
- 元数据四件套:owner、last_verified、review_cycle(90/180/365)、status(verified|needs-review|deprecated);"一键仍有效"把复核成本压到一次点击(Comala/FreshPage 模式)。[机] — 本 PRD 采纳(FR-C1/C2)。
- 衰减是复利回路:搜索持续排序旧页 → 读者失信 → 写新页而非改旧页 → 重复页分裂维护。**早期告警指标:** 孤儿页率与零点击搜索率,优于页面年龄。[机:采集] [义:归档决策]
  - **本项目差异(诚实记录):** 我们无搜索点击数据(消费发生在平台侧会话中,不回流)——"零点击搜索率"不可得;孤儿率可得。不得假装拥有该指标。
- 归档优先策略:无主 + 90 天零访问 + 复核失败 + 已被取代,任两条即批量归档 + 一周异议期,被取代页留 redirect 注记。[机] — 本项目无"访问"信号,归档策略需改用可得信号(复核结果、替代状态、无主),归入 D 域巡检的远期增强。

**概念分叉与合并**
- 身份阶梯:声明 ID → 归一化名 → 别名表 → 属性/坐标,逐级降级匹配;别名登记表反哺后续入库。[机] — 本 PRD 采纳别名表(FR-A2)。
- 三档置信:精确自动合并;模糊生成 proposal 等人工 apply;语义进拒斥区排队。生产经验 80–90% 可自动,其余人工。[机:proposal] [义:批准]
- 合并机械动作:重定向出入边、去自环重边、canonical 取连接度最高者(保留被并方全量 provenance)、冲突属性按置信度并置而非择一。[机] — 采纳(FR-D2,canonical 规则部署期钉死)。
- 本体变更走语义化版本 + 迁移脚本;实体拆分/弃用同样需要支持。[义]

**增量编译**
- 主失败模式是复利:漏匹配 → 重复实体 → 后续匹配率更低;错误映射被后续融合复用 → 局部错误放大。LLM 抽取的幻觉内容"结构上像样但违反本体",事后极难查。[义:检出] [机:指标监控]
- 对策:文档级子图隔离,只重编受影响子图,其余复用(成本正比改动量);入库幂等(append-only manifest,重跑即 no-op);canonical 形态强制;健康指标盯巨分量增长与重复率。[机] — 部分采纳;子图隔离属架构方案,转设计阶段评估。

**自治产品对照**
- NotebookLM:无 staleness 感知、无活同步,不知谁取代谁——反面教材。
- llm-wiki/Obsidian 三层架构(immutable raw / LLM 拥有的 wiki / derived output):ingest 时"重写旧页、清算矛盾、标记 stale",health 命令全库体检。**结论:RAG 架构下矛盾检测"不可能",wiki 架构下可行——okf-kb 的结构性优势。**
- Obsidian 生态:orphan 列表只作 triage 队列,不作删除清单。[义]

**主要来源:** Conflict-aware enterprise retrieval (zenodo 22609139);ConflictRAG;TMS/AGM 综述;Graphiti/Zep 双时态;Comala 内容过期工作流;FreshPage;wiki rot 指南;KGpipe 增量衰减(VLDB 2026);实体消解生产实践。

## 2. 机制细节(供架构阶段,不进 PRD 主体)

- **入库比对的实现形态候选:** (a) 建图代理在 ingest 流程内多一步显式工具调用;(b) capture 后独立比对步骤。两者对"比对记录存在性"的机械检验方式不同——(a) 依赖流程产物,(b) 可独立断言。倾向 (b):可独立断言,且不依赖模型自觉。待设计阶段裁定。
- **比对记录的产物形态:** 随批次产出的结构化文件(逐原料一行:命中页、结论、依据摘要),与批次报告同级、同批次 ID。检验点:原料数 vs 记录数的对账。
- **替代链字段的接入形态:** 预研两个选项——(1) frontmatter 扩展字段 `supersedes`/`superseded_by`(OKF 模式需放行扩展);(2) 复用 `sources`/trust family 表达。选项 1 语义清晰但涉及模式校验扩展;选项 2 不新增字段但语义挤占。**待 Q-E4 实测裁定。**
- **静默禁令的机械对账:** 门扩展项的判据草案:本批 diff 中对既有页正文的删除行,与冲突清单裁决记录对账——存在无记录的删除即阻断。实现依赖批次前后快照(与一期门 6 同机制基线)。
- **消费侧标注字段形状(草案):** 返回 matches[] 元素增可选字段 `flags: [{kind: "superseded"|"disputed"|"stale", detail, since}]`;召回排序中 deprecated 后置、stale 降权。"不破坏既有契约"的边界:既有字段不动,新增字段可选出现。
- **复核队列的调度:** 与批次串行(单写者);周批节奏下队列按周刷新。

## 3. 被拒方案与理由(记录以免重复讨论)

| 方案 | 出处 | 拒绝理由 |
|---|---|---|
| 时间新者胜(自动按时间选边) | 调研:时间型冲突最常见 | 时效 ≠ 正确;新旧并存本身可能是真实业务状态(历史方案仍适用特定场景) |
| 自动裁决替代关系(即使高置信) | 本文 FR-B2 | 替代判断含业务语义(V2 是否真的取代 V1,还是并存);误判代价不可逆 |
| 消费侧隐藏 deprecated/stale 页 | 本文 FR-B5 | 造成知识真空;用户有权知晓"曾有被替代知识";且隐藏使替代链的可见价值归零 |
| "到期后仍被召回则自动续期" | 本文 FR-C2 | 被检索 ≠ 被验证——恰恰是被反复消费的过时页危害最大 |
| 自动合并语义相似页 | 本文 FR-D2 | 语义合并不保证正确,且合并破坏 URL/引用,误伤面大 |
| 双时态查询(as_of) | 调研:Graphiti/Zep | 复杂度与收益不成比例;替代链 + 事件溯源已覆盖审计需求 |
| 跨库冲突治理 | 一期非目标 | 无跨库统一图谱;库级隔离是架构前提 |
| 归档策略照搬"零点击搜索率" | 调研:衰减早期告警 | 我们无消费侧点击数据回流,该指标不可得——不得假装拥有 |

## 4bis. 静态验证实现注记(2026-10-12,证据见 `verification-notes.md`)

- **更新路径三候选的细节(Q-E9 的评估底稿):**
  1. *扩展写侧工具*:bundle 是单文件(无扩展点),新增 update/merge 类工具的形态=打补丁(与 wiki_read 同法,单 hunk 级);维护成本=每次重打上游 bundle 重放全部补丁。
  2. *受控编辑+重建*:直接改 `wiki/**/*.md` 后触发 `wiki_rebuild_meta`(registry 全量重扫,内容会被收录);**代价=events.jsonl 无正文、无历史,归因靠外部治理台账**。**动态实测(2026-10-12)全链路走通**:概念页内容合并、aliases 增补、status 置位、superseded_by/stale_after 写入——全部被 registry/iwe 收录识别;代价坐实(手写编辑与 rebuild 在 events.jsonl 零记录)。**且发现:该路径即官方降级流程**——`wiki_ingest` 模型不可用时的指引本身就是让调用方 agent 手工编辑 `wiki/` 文件,候选 2 具"流程内合法性"(验证记录 §3.3)。
  3. *上游贡献回主干*:周期长,但一劳永逸;适合与上游有渠道时。
- **capture 无去重的编排层含义**:一期 FR-3"内容指纹跳过"与二期 FR-A4"重跑幂等"都必须在编排层自建(源 key + 指纹登记 + 跳过逻辑),不能指望 capture_source 工具;重跑会产生重复 SRC(验证记录 二.2.9)。
- **lint 的 contradiction 形态**:仅"字面标记的呈现",无内容比对——语义矛盾检测只能靠入库比对纪律(FR-A1)+ 人工;机械层最多做"标记与裁决记录一致性"的对账(验证记录 二.2.6)。
- **补丁点(消费侧标注 FR-B5)**:`searchWiki` 返回组装 map(`mcp-server.mjs:236843` 起)——**已实测**:单锚点替换约 15 行(新增 `flagsOf(entry)`,读 `entry.status`/`entry.stale_after`/`entry.superseded_by` 组装 `flags: [{kind, detail, since}]`),覆盖 recall(经 layered)/search 全部消费路径;副本冒烟通过,其余页契约不变(验证记录 §3.5)。冒烟脚本的 REQUIRED_TOOLS **未含 wiki_read**(仓库已打该补丁而断言未同步)——作为维护项补上,并新增"标注字段存在性"断言。
- **动态验证的环境方法**:`WIKI_ROOT=<试验库路径> node mcp-server.mjs`——WIKI_ROOT 是唯一指定 vault 的手段(验证记录 二.2.8);iwe 无 `--root`,须 `cd` 进库根执行。
- **模型降级的既有形态**:ingest 在模型不可用时**不报错**,返回 "⚠️ No background LLM available" + 手工指引(验证记录 二.2.10)——二期的比对纪律(FR-A1)需同样的"启动断言 + 记录存在性检验"防御,不能靠工具报错。
- **文档漂移两处**:①建库指南 L142"手写进不了图谱"与实测矛盾;②`docs/pi-llm-wiki/api.md` 描述的 recall 包装层与 MCP 实际返回不一致。**回写建议**(不擅自改一期 final 文档):建库指南修正表述;api.md 标注 MCP 版差异。
- **动态验证新发现(2026-10-12,试验库;详证见 verification-notes.md §3.6):**
  - *体系挂载硬规则*:inclusion 必须**裸链接独占一行**;`- [x](y)` 列表项不构成 inclusion(三写法受控实验)。挂载实践须强调,否则体系边静默丢失。
  - *root index.md 不可手写挂载*:llm-wiki `rebuild_meta` 会**重写根 index.md**(固定 Directories 形态),手写追加的体系链接被冲掉(实测两次)——建库指南 §2 第 5 条做法不可存活,需流程补偿或改挂方案;直接后果=体系页在 lint 报 orphan。
  - *iwe 校验与规范偏差*:`stale_after` 被 iwe schema 硬校验为 `date`(仅 YYYY-MM-DD),ISO8601 时刻会 validate 失败;门机制可用(失败退出码 1 + 精确错误 + hint)。
  - *消费现状量化*:deprecated/stale 写入后检索零变化(被替代旧页得分 92→102,反超现行方案);业务代码对两字段零消费 → FR-B5/C3 是纯新增改造。
  - *查重纪律*:recall(词法)对换叫法鲁棒、search(registry)漏检显著;recall 混合个人库命中(带 `vaultLabel`);aliases 登记后换叫法得分 26.6→151.6 并置顶(FR-A2 实证)。
