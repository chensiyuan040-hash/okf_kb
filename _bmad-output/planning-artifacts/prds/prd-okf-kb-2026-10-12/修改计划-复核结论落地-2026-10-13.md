### P0-2 消费协议上墙【本机产出卡片 → 内网落地】

**依据**:问题 1/4/18——recall 零警示、preview 靠巧合、骨架页 Auto-preview 有误导空间;库在用,防误导 = 0。

**协议正文(五条硬纪律,给用库 agent 的系统提示/会话模板)**:

```
1. 必须 recall 定位 → wiki_read 读全文 → 再回答;禁止只凭 preview 摘要作答。
2. 见到 flags / status: deprecated / superseded_by / stale_after 字段,必须向用户提示"该条已废弃/过期/被替代"。
3. 见到 vaultLabel(如 "📓 personal")的非本库条目,必须过滤或明确标注来源,不得当作本库内容。
4. 多来源内容矛盾且页面无任何标注时,禁止自行裁断;列出来源、声明"库内未标注裁决,请人工确认"。
5. status: skeleton 的页面(正文为 [LLM: …] 占位符)不当内容使用;即使其 Auto-preview 摘要看起来完整,也须报告"该页未整理"。
```

> 注:第 2 条中的 `flags` 为 **P1-2 补丁部署后**才存在的字段;在此之前,消费 agent 以 `wiki_read` 读到的 frontmatter(`status`/`superseded_by`/`stale_after`)承担提示义务。

**产出物**:`docs/消费协议卡片.md`(或并入建库指南 §8);内网落点 = 用库 agent 的系统提示/会话开头模板。

**验收**:克隆库构造一个旧版页,消费 agent 按协议回答时主动带出替代提示、正确过滤跨库条目(不误当本库内容)、不误用 skeleton 页。

### P1-1 替代工作流三件套规范 → 写进建库指南【本机】

**依据**:问题 6(无自动接替);112 页全 stable = 第一次替代尚未发生,这是最后窗口期。

**规范内容(替代发生的同一批操作内完成,不许分开做)**:

| 角色 | 动作 |
|---|---|
| 旧页 | frontmatter 写 `status: deprecated` + `superseded_by: <新页ID>` + `stale_after: <日期>`;正文开头引用块加"本方案已被《新》替代" |

**验收**:建库指南更新;克隆库构造场景实测全链路(检索/树/校验)。

### P1-2 flags 补丁采纳【本机出补丁 → 内网部署】

**依据**:问题 4/5(两轮验证纯叠加:仅旧页多出 `flags`,分数与排序零变化)+ **SPEC §11 "SHOULD surface"**——采纳即补齐规范要求,非新发明。

**动作**:

1. 把补丁落成**正式补丁文件**,与 `wiki_read` 补丁同一流程管理(见 `tools/pi-llm-wiki/CHANGELOG.md`)。机制:recall 返回条目按 frontmatter 注入 `flags: [{kind, detail, since}]`,纯叠加(分数与排序零变化,问题 5 已证)。两个落地要点:
   - **种子**:本机 `/home/huangyu/okf-lab-vault/mcp-server-patched.mjs` 内的 `flagsOf()` 即实测实现;复核侧自构造副本已随复核清理(报告自述),以本机种子为起点;
   - **覆盖补全**:种子对“仅 `status: deprecated` 而无 `superseded_by`”的页会输出 `{kind:"superseded", detail:null}`——落正时改标 `kind:"deprecated"`(deprecated 不必然有后继;补齐后 SPEC §5.4 的 deprecated 才真正被检索层 surface);
2. 内网替换标准 bundle,冒烟 + 构造场景验证 flags 出现。

**验收**:patched bundle 冒烟通过;旧页条目带 flags、其余条目与分数逐位不变;`deprecated`/`superseded`/`stale` 三种 kind 各构造一页可见;重打流程文档化。

## 4. P3 — 判断力基线(回答"AI 哪些能判断")

**依据**:验证报告 v2 问题 18 + 复核报告问题 18——判断可靠性 = 信号存在 × 信号到达 × 信号显著;强模型读全文能判对,但无结构保证。

**方法**(复核报告已示范克隆 + 隔离):

1. **克隆真实库**至隔离区(先例 `/tmp/okf-verify/vault`,零污染);
2. **构题**:用真实主题,每个场景 2~3 问——开放式("XX 怎么用?")/ 点名式("老的还在吗?")/ 陷阱式(问一个 preview 命不中、只有 frontmatter 才有的信息);
3. **隔离会话**:只给问题、不预知库内结构,仅凭只读工具自行检索;
4. **双模型对照**:Claude vs 内网目标模型,差集 = 弱模型新增盲区;
5. **观测三点**:调用轨迹(是否 read 全文)/ 结论正确性(对照人工黄金答案)/ 不确定性声明。

**产出**:判断力基线表(场景 × 能判/不能判 × 证据);此后换模型、改内容结构后重跑 = 知识库的回归测试。

**可预填部分**(复核报告问题 18 已证):强模型 + 读全文 → 新旧判断 ✅;只凭 preview → 靠运气;无标注矛盾 → ❌ 不可判(应走流程层人工裁决)。
