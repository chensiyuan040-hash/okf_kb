## D1 增量语义：身份关联归工具，内容处置归会话

- fetch 只管拉（读游标→增量过滤→落地+清单→推游标）；**不查重**。
- 身份关联 = 库内 source 页 frontmatter 的 `origin_url`/`page_id` + `source_updated_at` 机械比对（grep），fetch 在增量清单里直接标注分类。
- 内容处置（演进/并列/跳过）归会话，走指南既有纪律（`## Evolution`、同结论合并不写演进）。
- **没有 keymap 第二状态**：源 key → SRC 的映射载体就是库内溯源元数据（随 capture 生成、随 git 留痕）。游标文件只是拉取效率优化，丢了不丢数据（多拉一轮，幂等兜底）。
- 幂等闭环：SKILL.md 既有纪律"capture 后移走 raw-inbox 原件（done/）"。

## D2 全量→增量：时间水位线规则（CF/NC 定稿）

```
全量（冷启动）：
  按 space（CF）/目录（NC）分批：拉一批→消化完→下一批；不一次性倒满 raw-inbox
  游标基线 T0 = 拉取时刻的源侧时间；全量期间不追新，存量清完后第一轮增量从 T0 补

增量（统一规则）：
  分割线 T0 = 上一轮拉取完成时的【源侧】时间（非本机时钟）
  本轮 = 源侧时间戳 > T0 − overlap（10 分钟重叠窗口）
  CF：CQL lastModified（页面内容版本，不含评论——本期只要正文，恰好）
  NC：WebDAV getlastmodified
```

钉死的三细节：
1. **T0 取源侧时钟 + 宁重不漏**：时钟偏差/同秒边界由 10 分钟重叠吸收；重复候选由身份关联挡掉。
2. **NC 移动盲区**：mv 保留 mtime → 移动的文件新位置发现不了；一期接受（与"删除/移动不管"同决定），将来要补=低频全目录对账。CF 无此问题（页面移动不变 pageId，lastModified 更新）。
3. CF lastModified 不含评论；将来要评论需单独拉。

`source_updated_at` 的角色 = 增量比对机器端点（库内旧值 vs 源侧新值）。

## D3 四源机制分类（禅道/BM 留口，不写代码）

| | 在线拉取型（CF/NC/禅道） | 人工批次型（BM） |
|---|---|---|
| 增量边界 | 时间线推断（T0+overlap） | **显式批次**——人工放进 inbox 的那批 |
| 身份关联 | origin_url/page_id + source_updated_at | **内容哈希**初筛 + 会话语义判定 |
| source_updated_at | 比对端点（机器裁决） | 降级为展示性溯源（运输污染时间戳，不可信） |

- 禅道：机制可延用，**语义要重写**——①状态流转噪音（bug 激活→修复→关闭全更新 lastEditedTime，照搬演进纪律会淹没库；方向：终态捕获/状态折叠）②聚合粒度（N 工单→聚合页，非一 bug 一页）。禅道线是一次真正的重新设计。
- BM：保密约束优先（secret-vault unseal 会话内跑，tmpfs 零明文）；哈希可重算依赖"raw 不可变存原件"；人工声明只作辅助信号。
- 四源共享的只有机械组件思想（时间过滤/身份关联/SRC 落库/幂等）；一期 CF/NC 不为后两者预留任何代码。

## D4 溯源字段与 capture 结构（对齐 main 补丁 + 三处修正，定稿）

背景：`/models/app/okf-kb/wiki` 库 111 源以 file_path 方式导入 Confluence 导出件，溯源全缺；
诊断与回填方案见存档文档。main 上今天已落 capture 四参数补丁（22a6b66+2b7a87a，当前 rework
分支缺，开工前先合入）。

### 字段裁决

| 语义 | frontmatter（定稿） | manifest | 说明 |
|---|---|---|---|
| 原文 URL | `origin_url` | `url` | 从 main 补丁命名（SKILL.md/CHANGELOG/重打流程三处绑定）；不用 `url`/OKF `resource` |
| 作者 | `author` | `author` | 存量按空间推断（仅个人空间填）；增量走 API 真实值（version.by）——两层不同不混用 |
| 来源系统 | `source_system` | `source_system` | confluence/nextcloud/zentao/bm |
| 源侧修改时间 | `source_updated_at` | — | 增量比对端点；**存量回填不写**（导出数据无源侧时间，不冒充） |
| 页面 ID/空间/版本 | `page_id`/`space`/`source_version` | `source_meta` 子对象 | 经 `source_meta: {k:v}` 通用参数透传，frontmatter 扁平铺开 |

### 三处修正（对上轮讨论稿）

1. **`source_meta` 通用透传，不逐个加显式参数**：page_id/space/source_version 是 Confluence 特有，
   显式进 capture schema = 通用层加源特例（旧 pipeline 老路）。四个源无关通用语义保持一等参数
   （origin_url/author/source_system/source_updated_at），源特定 kv 走 source_meta——bundle 一次
   改完，此后不为任何新源动通用层。
2. **存量回填后时间端点缺失，第一轮增量处置**：库内已有 page_id 但无 source_updated_at 的文档，
   兜底=一律当"候选修改"（capture 新 SRC+读后裁决，一次性代价）；可选优化=API 接通后按 pageId
   拉 version history 回补时间戳再跑增量。
3. **巡检"缺 origin_url 告警"豁免 BM**：BM 无可访问 URL 是常态，不豁免则永久误报（按库配置豁免
   或只对 source_system≠bm 计数）。

### bundle 补丁增项（登记进 CHANGELOG 重打序列）

- `source_meta` 可选参数（manifest 子对象 + frontmatter 扁平铺开）；
- file 型捕获当 origin_url 存在时，skeleton 正文渲染 `> _Original: [标题](url)_` 行（上游仅 URL 型自带）。

### 存量回填（按存档方案 §3，字段名对齐）

- 脚本 `scripts/backfill-provenance.py`：解析优先级=正文"来源"行 > 文件名前缀（pageId 111/111 实测）；
  幂等、dry-run 同构、逐 SRC 输出一行；默认只改 wiki 层，`--with-raw` 可选；
- registry 手动同步对应条目，接受扩展重建覆盖（消费不依赖它）；
- 不写 source_updated_at；不引入 `url_unknown: true`（省略即未知）；
- **先回填后启用 schema**（顺序敏感）：`source.yaml` 只 `required: [type]`，origin_url 带
  `^https?://` pattern 但不强制（BM 必须能省略），config.toml `[schemas.source]` 绑定 `sources/**`。

### 各源适配（字段全 optional：缺即整个省略，不写空串不造假值）

| 源 | origin_url | author | source_meta | source_updated_at |
|---|---|---|---|---|
| CF | viewpage URL | version.by | page_id/space/source_version | lastModified |
| NC | WebDAV URL（可构造） | owner（格式存疑则省略） | 目录可当 space | mtime |
| 禅道 | 工单页 URL | openedBy | 实体 id 放法到时再定 | lastEditedTime |
| BM | 无（省略） | 大多无（省略） | — | 不可信（省略） |

## D5 工具层接口定稿

- **选型**：Python 标准库单文件（urllib/xml.etree/json/re），**零 pip 依赖**；bash（WebDAV XML 灾难）与 node（无 XML 解析）出局。每源自包含，放 `tools/sources/<源>/`。
- **CLI 统一约定**：`--vault`（默认=cwd）/ `--space` / `--full` / `--since` / `--limit`（保护上限,默认 500,**非分批机制**）/ `--dry-run`。
- **参数自解析三归属**（会话里一条指令跑全程,人不记参数）：
  - `--vault` 默认当前目录（建库会话本在库根开）；
  - 凭证：fetch.py 按自身路径定位仓库根 `.env`（`../../.env`）,自解析 KEY=VALUE；
  - space 清单等业务参数：写在**库根 CLAUDE.md**"本库范围"节（skill 读它）。
- **游标**：vault 根 `.fetch/<源>.json`（gitignore）——库-源对的状态,随库走；丢失=多拉一轮幂等兜底。
- **.env**：仓库根一份多源前缀（CF_BASE_URL/CF_TOKEN、NC_BASE_URL/NC_USER/NC_PASSWORD）,0600,gitignore,`.env.example` 进 git；BM 凭证不落此（secret-vault 自管）。
- **双落模式（两源统一）**：`原件 + 可读版`（CF: `.html` 原样 + `.md` 机械剥标签版；NC: `.docx` + `.docx.md` pandoc/mammoth 转换）。纯格式转换无语义,原件留档可重转,转换器源私有不进通用层。
- CLI 形态对 Claude Code 最优：Bash 工具直调、非交互、stdout 摘要 + 非零退出码即协议。

## D6 skill 工作流定稿

- **载体与分发**：母版在 okf-kb 仓 `.claude/skills/kb-sync-<源>/SKILL.md`；建库时软链到库根 `.claude/skills/`（不支持则复制）。**CLAUDE.md 记库事实（space 清单）,skill 记流程**——skill 零库特定配置,跨库通用。
- **三段结构**：
  - A 获取（Bash 一条）：增量=无参 fetch（游标驱动）；全量=逐 space `--full --space`；fetch 非零退出→如实中止不进 B；
  - B 消费（MCP+指南纪律）：读 manifest 三分类——skip 不动 / new 先搜后建 / changed 先读后并；capture 带 D4 全参数；**每 10~15 份一个 checkpoint commit**；
  - C 收尾：批次目录→done/ → gate.sh → 归并清单 → 终 commit。
- **重入规则**：批次目录在 raw-inbox/ 未移 done/ = 未完成；重入逐项重查 page_id（capture 前查重纪律兜底）。断点状态零新机制。
- **全量分批裁决**：fetch 内部分页拉完整个 space（--limit 仅保护）；消化分批是会话侧行为；**全量 T0 = 首 space 拉取完成时刻**；全量切增量零显式动作（游标即状态）。
- **前置检查**（阶段 A 前）：存量已回填 page_id（否则第②道去重闸失效,skill 提示先回填）。
- NC 线同构复用 A/B/C 骨架,差异仅 fetch 版本/目录保留/读转换版;skill 独立一份。

## D7 增量去重：三道闸串联

```
源全部页面 → ①水位线(lastModified > T0−10min) → ②身份关联(grep 库内 page_id):
   库内有 id 且时间相同 → skip(不落地) / 有 id 且源侧更新 → changed(演进裁决) / 无 id → new
   → ③会话撞题预检(SKILL.md 既有纪律)兜机制失手
```

- 三道全漏最坏 = 同内容双 SRC → 指南既有处理（同结论合并、回源并列）+ 归并清单人审,不会出现重复知识页。
- **顺序铁律：存量先回填 page_id,第②道闸才有比对键**——未回填跑增量 = 111 存量全标 new 全部重复 capture。
- 第一轮增量特殊态：存量有 page_id 无 source_updated_at → 一律 changed（候选修改）,读后裁决,一次性冗余,之后时间链完整。
- 两层"重复"辨析：SRC 层多包 = 设计内版本历史（Evolution/并列）；知识页分叉才是污染,由 ingest 纪律管,与增量机制无关。
